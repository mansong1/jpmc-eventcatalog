## Overview

Nobody hand-writes a pipeline. The everyday path is a saved pipeline plus inputs: `harness execute pipeline deploy_ecs --input env=jpmc_prod --input image_tag=<tag>`, or `--input-set main --input who=<you>` for the laptop pipelines. From an assistant, the Harness MCP server does the same with `harness_execute(resource_type=pipeline, action=run, resource_id=<id>, inputs={...})`, which resolves the runtime inputs for you.

The same CLI approves or rejects approval steps and retries stages. One-off YAML runs as a dynamic execution of the shell pipeline `ec_dynamic` (`harness execute pipeline:dynamic ec_dynamic -f pipelines/dynamic/smoke_envs.yaml`; CLI only, no MCP equivalent), and the executed YAML is stored on the run. Dynamic runs take no input sets or runtime inputs, so the values live in the reviewed file. On-run OPA policies evaluate that YAML like any saved pipeline.
