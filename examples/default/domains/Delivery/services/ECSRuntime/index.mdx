## Overview

| Environment | Strategy | Port | Flow |
|---|---|---|---|
| dev | rolling (`deploy_ecs`) | 8198 | rolling update |
| staging | blue/green (`deploy_ecs_bluegreen`) | 8197 test → 8199 live | new service on the idle TG behind :8197, verify, swap target groups, verify :8199, downsize the old service after 300 s |
| prod | canary (`deploy_ecs_canary`) | 80 | one-task canary in the live TG, verify until a request hits it, delete the canary, roll the primary, verify |

Rollbacks: staging uses `EcsBlueGreenRollback` (a listener swap back). Prod uses `EcsCanaryDelete` + `EcsRollingRollback` under `spec.execution.rollbackSteps`, which policy `jpmc_block_prod_without_rollback` enforces. Each deploy records evidence (`/version.json`, `DEPLOYED_AT`) for the next [[service|promotion-gate]].
