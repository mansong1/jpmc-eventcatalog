## Overview

**Clone to governed release** is the whole delivery path for this catalog. A change is reviewed as a running preview before merge. It is then built and scanned **once** as `rc-<sha>`, and that tag is promoted through dev, staging and prod. Each promotion is judged by policy on what the previous environment is serving *now*.

<NodeGraph />

## How it works

1. A PR triggers [[service|pr-preview]], which publishes [[event|preview-deployed]] and waits up to 24h for [[event|preview-accepted]] or [[event|preview-rejected]].
2. [[event|merged-to-main]] starts [[service|rc-build]]. If the gates pass, it publishes [[event|release-candidate-built]].
3. [[service|ecs-runtime]] deploys to dev (rolling). Then [[service|promotion-gate]] promotes to staging (blue/green) and, after a 180 s soak, to prod (canary).
4. Any failure ([[event|gate-failed]] or [[event|promotion-denied]]) chains [[service|rc-autofix-agents]], which either raises [[event|autofix-pull-request-raised]] or hands off to a human.
