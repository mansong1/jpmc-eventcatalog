## Overview

The **Delivery Platform** domain models the system that builds, previews, gates and deploys this EventCatalog site. Each service is a Harness pipeline (or pipeline stage), and each message is a hand-off between them: a trigger, an approval outcome, a policy decision or a deployment record.

| Component | Responsibility |
|-----------|----------------|
| [[service\|delivery-cli]] | the `harness` CLI and MCP server start saved pipelines with inputs; one-off YAML runs dynamically |
| [[service\|pr-preview]] | Functional build (Cloud or Mac), IaCM slot, ECS preview, 24h review |
| [[service\|rc-build]] | Quality and STO gates, then one immutable `rc-<sha>` image |
| [[service\|promotion-gate]] | Approval or change window → fresh evidence → OPA policy |
| [[service\|ecs-runtime]] | dev rolling, staging blue/green, prod canary |
| [[service\|release-orchestration]] | The same artifact through phases `jpmc_rc` → `jpmc_staging` → `jpmc_prod` |
| [[service\|rc-autofix-agents]] | Triage → fixer → guardrails → GitHub PR (Cloud or Mac) |
